# Backend, services, state & Cloud Functions

## Layers

```
screen → *Controller → service/*  → backend/repo/* → Firestore / Storage
                     ↘ state_management/* (ChangeNotifier caches, used via Provider)
```
Repos (`lib/backend/`) are thin Firestore/Storage wrappers (throw generic `Exception('Failed to ...')`, swallowing stack traces). Services (`lib/service/`) add logic and wrap errors in `EventServiceException` / `StireServiceException` (`lib/exceptions/`). Many controllers `new` their services directly (`TeamService()`, `EventService()`) instead of using Provider — services are stateless so this works, but `EventService`/`NewsService` are *also* provided in `main.dart` for `EventList`/`NewsList`.

## backend/
- `authentication/AuthenticationRepository` — FirebaseAuth email/password (`register`, `loginWithEmailAndPassword`) + Google (`signInWithGoogle`), `logout` (deletes this device's `pushTokens` doc first with `FCMService.forgetTokenOf`, 3 s at most; signs out of Google and Firebase; then `FCMService.dropDeviceToken` makes a new token, not waited on; nothing in it can block or fail the sign-out), `authUser`. Maps Firebase error codes to English `Exception` messages.
- `repo/`
  - `event_repo` — `events` CRUD, `stopEvent`, `streamEvent`.
  - `teamRepo` — `events/{id}/teams` CRUD, streams (`getStreamTeam`, `getStreamTeamsForEvent`, `streamLastMessage` — a chat's newest message, `orderBy timestamp desc limit 1`, for the organiser's conversation list), `setPhotoApproval` (updates `photoApprovals.<key>` via dotted path), `updateMissionProgress/PuzzleNumber`, `startTeam/finishTeam`, `updateTeamLocation`, `addUserToTeam` (arrayUnion), `isTeamNameTaken` (returns **true on error**), `getUserTeamForEvent` (query `userIds array-contains uid`).
  - `push_token_repo` — `PushTokenRepo.save(token, uid)` (set `pushTokens/{token}` = `{uid, updatedAt}`) and `delete(token)`.
  - `user_repo` — `saveUser`, `findByEmail` (null only when there is no such user; a failed lookup throws `UserLookupFailed`), `addEventToUser/removeEventFromUser` (arrayUnion/Remove), `deleteLegacyTokens` (deletes `fcmToken` / `fcmTokens` from the user's own doc when there), `getRegisteredEventsFromUser` (legacy; reads fields `title`/`date` that Event docs don't have).
  - `messages_repo` — `sendMessage`, `sendPlayerMessage` (the message, then `unreadByAdmin.text/at/count` (count +1) as its own write, so a refused mark never loses the message), `sendToTeams` (one batch), `getMessages` stream.
  - `stire_repo`, `news_category_repo` — `stire` / `categories` collections.
- `functions/team_functions.dart` — `TeamFunctions`, a thin wrapper over `FirebaseFunctions.instance.httpsCallable(name)` (package `cloud_functions`): `checkTeamName`, `createCrew`, `registerTeam`, `previewInvite`, `joinTeam`. Each returns the decoded `Map<String, dynamic>`, no logic. Errors arrive as `FirebaseFunctionsException` with `details['reason']`.
- `repo/crew_repo.dart` — `CrewRepo.streamUserCrews(uid)`: `crews` where `memberUids` array-contains `uid`, ordered by name (read-only; crews are written by functions).
- `storage/storage_images.dart` — `ImageRepo.uploadImage` / `uploadStireImage` (see `data-model.md`).
- `functions/notification_functions.dart` — `NotificationFunctions.send(title, description, eventId?)`, the `sendNotification` callable; failures surface as `FirebaseFunctionsException`.
- `functions/src/notifications/inbox.ts`: each player's notification list (`users/{uid}/notifications`). `addToInboxes` (batched, never throws), `pushToUser` (to every device of the user, `tokensOfUser`, with `data`; never throws), `pushData(item)` (`{type: kind, eventId?, teamName?}`, the data a tap opens), `chatInboxItem`. `sendNotification`, `onChatMessage` (organiser messages), `notifyCaptain`, `registerTeam` and the results all add to it.

## service/
- `event_service/event_service.dart` — CRUD wrappers; `publishEvent` refuses an event with `publishProblems`, generates an id if empty, then uploads images and saves it (the only way a new event goes live); `updateEvent` uploads images then `set`s the whole doc, and its caller first runs `checkLiveEdit`; `registeredEventsFromUser(allEvents, user)` maps ids → events.
- `event_service/upload_images.dart`, `news_service/upload_news_images.dart` — local-path → Storage URL replacement.
- `team_service/team_service.dart` — pass-through to `TeamRepo` plus: `deleteTeam` (removes the event from every member's `registeredEventIds` first), and the callable-backed methods: `registerTeam(...)` → `RegisterResult`, `isTeamNameFree(eventId, name)` (`bool?`, null on a network error), `previewInvite(code)` → `InvitePreview`, `joinTeam(code)` → event ids joined, `createCrew(name)` → `(crewId, inviteCode)`, `streamUserCrews(uid)`, `getTeam(eventId, teamName)` (one team as saved, null when missing). Codes go through `normaliseCode` first. Constructor `TeamService({TeamFunctions? functions, CrewRepo? crews})` so tests can inject fakes.
- `team_service/team_errors.dart` — `enum TeamError` (the 14 function `reason`s plus `network`, `unknown`), `TeamError.fromException(e)` (reason from `details`; `unavailable`/`deadline-exceeded` → `network`; else `unknown`), `TeamError.teamNameFrom(e)` (`details.teamName` of `alreadyInTeam`), and `teamErrorText(error, {teamName})` with the Romanian message for each.
- `team_service/invite_preview.dart` — `InvitePreview` (`crewId, crewName, captainName, members, alreadyMember, event?`), `InviteEvent` (`eventId, name, dateEvent, teamName, size, count`), `slotLine` ("1 din 4 · tu ești al 2-lea", "primul" for the first) and `isFull`. `team_service/register_result.dart` — `RegisterResult` (`teamName, crewId, inviteCode, skippedUids`).
- `news_service/news_service.dart` — `getAllStire`, `createStire` (id + upload + save), `updateStire`.
- `message_service.dart` — builds `Message` from the user's role, signing a player's with `senderOf(user)` (uid + first name); a player's text, and a player's photo from the chat's photo button, marks the team unread; `sendImageMessage` for photo puzzles (with the approval key, not marked unread: the pending approval flags the team) and the chat's photo button (`text: 'Fotografie'`, no key); `announce` posts to many teams.
- `FCMService.dart` — static: `getFCMToken()` (asks permission), `saveTokenAsking(uid)` (sign-in and sign-up, Google included), `saveTokenOnStart(uid)` (each start, from `AuthUtil`, never asks; also deletes the older tokens from the user's doc), `saveTokenAfterPrompt()` (right after `StartupPermissions` asks for notifications, for the signed-in user), `forgetTokenOf(uid)` (sign-out, 3 s at most) / `dropDeviceToken()`. Every save is `PushTokenRepo.save`. `initNotifications()` never throws (and `main` guards it too): iOS foreground presentation (iOS shows its own banner, and a tap on it arrives through `onMessageOpenedApp`), local notifications initialised for Android and iOS (`DarwinInitializationSettings` asking for nothing; v19 throws without them), shown for foreground pushes on Android only with the push's data as payload and the `ic_stat_notification` small icon, `onTokenRefresh` saved on the signed-in user, taps from `onMessageOpenedApp`, `getInitialMessage` and the local notifications handed to `PushOpener`.
- `push/` — what a tapped push opens. `push_destination.dart` (pure, tested): `pushDestination(data, isAdmin:)` gives `PushChat(eventId, teamName)` for `chat_message`/`chat`, then for an organiser `PushNowhere`, for a player `PushMemory` (`results`), `PushEvent` (anything else with an `eventId`) or `PushNotifications`; `pushPayload` / `pushDataFromPayload` for the local notifications. `push_opener.dart`: `PushOpener.instance` holds a tap until `AuthUtil` has shown the first screen (`landed(signedIn:)`; signed out, taps are dropped) and owns `PushOpener.navigatorKey` (MaterialApp's `navigatorKey`). `push_navigation.dart`: `openPush` pushes `Routes.chatScreen` (an organiser's team by name, a player's own team by uid, so a rename still works), `Routes.eventDetails`, `Routes.memory` or `Routes.notifications`; what cannot be found sends a player to the list and leaves an organiser where they are.
- `LocationService.dart` — singleton; permission check, `startLocationTracking(eventId, teamName)` writes lat/lng to the team doc (distanceFilter 10 m), `stopLocationTracking()`. Started/stopped by `EventGameController`.
  - Settings: `positionSettings({distanceFilter, platform, web})` (top level, same file) is the one place they are chosen, for every stream and one-off fix. Android: `AndroidSettings`, accuracy `best` (all of high/best/bestForNavigation map to the fused provider's high-accuracy priority there), `intervalDuration` 2 s (`fixInterval`; the default was 5 s), distance filter kept. iOS/macOS: `AppleSettings`, accuracy `best` (`high` on iOS is only "nearest ten metres"; `bestForNavigation` was left out for battery over a 3 h game), `activityType: fitness`, `pauseLocationUpdatesAutomatically: false`, background updates and indicator off. Web and tests: plain `LocationSettings` with accuracy `best`. Only while the app is open; no new permissions.
  - `getPositionStream({distanceFilter = 10})` gives every reading; `accuratePositions({distanceFilter = 10, withCurrentFix = false})` passes them through `filterFixes` (`location_filter.dart`), and with `withCurrentFix` also asks `getCurrentPosition` at once so the first fix does not wait for the stream (its errors are ignored; the stream's pass through). The team position for the organiser's map (and the walk) uses `accuratePositions(distanceFilter: 10)`; the geolocation puzzle uses `accuratePositions(distanceFilter: 2, withCurrentFix: true)`. On Android, geolocator keeps one position stream per app: while the team tracking stream (10 m) is running, the puzzle gets that one, so its 2 m filter only applies when nothing else is listening.
- `location_filter.dart` — pure. `LocationFilter<T>` shows a reading when it is the first, at most 30 m (`worstAccuracy`), no worse than the one shown last, or without an accuracy (0); any other is held, and if nothing better comes within 10 s (`patience`) of the last shown one the best held one is shown (`offer`, `due`, `dueAt`). `filterFixes(stream, accuracyOf:)` applies it to a stream with a timer for the held reading, so it never gets stuck when no reading follows. The puzzle's circle check (`insideCircle` with `Puzzle.radiusMeters`) is unchanged; it only gets the better readings. Tests: `test/service/location_filter_test.dart`, `test/service/location_settings_test.dart`.
- `startup_permissions.dart` — `StartupPermissions.shared.askOnce()`: the phone's prompts for notifications, location while in use and camera, one after another, once per install (shared_preferences `startup_permissions_asked`); called after the first frame of `UserShell` and `AdminHome`. Never throws; one failed prompt does not stop the next. The flag store and the requesters are constructor arguments (tests). See platform-and-config.md, "Permissions at first sign-in".
- `route_service.dart` — singleton; OSRM public demo (`router.project-osrm.org`, foot profile), throttled to one request / 5 s (returns `null` when throttled), `formatDistance`.
- `share_service.dart` — builds the RO registration message; share sheet / WhatsApp / email / SMS. `shareInvite(context, code:, teamName:, eventName:)` shares the invite text ("Intră în echipa … deschide TeamXperience → Echipe → Intră și scrie codul …").

## state_management/ (provider)
Registered in `main.dart`:
`UserProvider` (ChangeNotifier) → `UserRepo`, `AuthenticationRepository` (Provider) → `AuthUtil` (Provider) → `EventService`, `NewsService` → `EventList`, `NewsList` → `UserEventsProvider` (+ a second, duplicate `NewsList` registration at the end).

- `UserProvider` — `currentUser`, `firebaseUser`, `isLoggedIn`, `setUser`, `clearUser`, `addRegisteredEvent`, `updateProfile` (takes a fresh copy's XP, stats and badges for the same uid; Profil calls it).
- `EventList` — cached `events` (5-min staleness; `loadEvents({forceRefresh})`, `refresh()`), `upcomingEvents`, `liveEvents`, `pastEvents`, `publishEvent/updateEvent/deleteEvent/getEventById`, `clear()` (called on logout).
- `NewsList` — same for `Stire`: `getNewsByType`, `getNewsByCategory`, `allNewsSorted`, `getLatestNews(n)`, `getNewsFromPeriod`, `createStire/updateStire/getStireById`.
- `UserEventsProvider` — listens to `UserProvider` + `EventList`; `registeredEvents`, `upcomingRegisteredEvents`, `pastRegisteredEvents`, `nextEventWithinHour`, `loadActiveEvent()` (async scan of started-and-not-finished teams — one Firestore query per past registered event on every change), `activeEvent`, `activeTeam`.

## functions/ (Firebase Cloud Functions v2, Node 22, TypeScript, `functions/src/index.ts`)
- `sendNotification` (callable, `functions/src/notifications/`) — input `{title, description, eventId?}`. Refuses anyone whose `users/{uid}.role` is not `ADMIN` (`notOrganiser`), a blank title or text or a non-text event id (`notificationInvalid`), and nobody to reach (`noRecipients`). Reads `users` (filtered by `registeredEventIds array-contains eventId` when given), collects every device of each (`tokensOfUsers`), sends via FCM multicast in chunks of 500 (`sendToDevices`, which also forgets tokens FCM calls gone), with data `{type: "admin_notification", eventId?, title, body, timestamp}`. Answers `{recipients, sent, failed}`.
- `onChatMessage` (Firestore `onDocumentCreated` on `events/{eventId}/teams/{teamName}/messages/{messageId}`, logic in `chat/chat_push.ts` `sendChatPush`) — if `sender == "ADMIN"` notifies every device of the team members (`team.userIds`), otherwise every organiser device; data `{type: "chat_message", eventId, teamName}`.
- `notifications/tokens.ts` — the devices of users. `tokensOfUsers(db, [{uid, data?}])` / `tokensOfUser`: their `pushTokens` (`where uid in`, 30 at a time), plus `legacyTokensOf(userDoc)` (`fcmTokens` and `fcmToken` older versions left) unless that token's `pushTokens` doc belongs to another uid now, once each. `sendToDevices` (500 per multicast), `goneTokens` (unregistered / invalid answers) and `forgetTokens` (deletes the `pushTokens` doc and pulls the token off older user docs). There is no trigger on `users`.
- Deploy: `firebase deploy --only functions` (predeploy runs `npm run build`). `functions/lib/` and `node_modules/` are build output.

## Security rules

`firestore.rules`, tested in `functions/src/test/rules.emu.test.ts`, one test per client write. Add to both together: a write a rule forgets fails silently on a phone in the middle of a game. In short: everyone signed in reads events, teams, news and seasons; a team member changes only the progress fields of their own team, and only as the app does (own `presence` and `walked`, a mission's time once, `hintsUsed` only added, photos only as `pending` with `lastPhotoKey` naming the try, the unread mark set but not cleared, its `count` only one more than before, `phoneNumber` for the captain, a mission's time only for the current mission with the server's clock); a user's own `uid` and `email` cannot change; organisers change anything but create no teams; `crews`, `inviteCodes`, `seasons`, `memories`, `xp`, `stats`, `badges` and `resultsComputedAt` belong to the functions. Rules cannot walk a map, so the size of `attempts` is not checked. Storage rules are not in the repo.

**The live rules open the whole database until 2026-12-31,** after which every request is refused. Deploy these before then.

## Team functions

Callables in `functions/src/teams/` (region `us-central1`). A refusal is `HttpsError` with `details: {reason}`, which `TeamError.fromException` maps; a signed-out call is `unauthenticated` with `notSignedIn`.

| Callable | Input | Output |
|---|---|---|
| `checkTeamName` | `{eventId, name}` | `{free, problem?: 'short'/'long'/'characters'}` |
| `createCrew` | `{name}` | `{crewId, inviteCode}` |
| `registerTeam` | `{eventId, name, size, phone, rulesAccepted, photoConsent, crewId?}` | `{teamName, crewId, inviteCode, skippedUids}`; a crew signed up under a new name takes it (as `renameTeam` does); its earlier teams keep theirs |
| `previewInvite` | `{code}` | `{crewId, crewName, captainName, members, alreadyMember, event?}` |
| `joinTeam` | `{code}` | `{crewId, eventIds}`; joining again returns the player's events |
| `renameTeam` | `{eventId, teamName, newName}` | `{teamName}`; only the captain, before the event or the team starts; the name must be free at the event (`nameInvalid`, `nameTaken`, `notCaptain`, `gameStarted`, `teamNotFound`); moves the team and its messages (marked `moved`, not pushed again) and renames the crew |

## Results

`onEventStopped` (when `isStopped` turns true) and `closeExpiredEvents` (every 15 minutes, events whose duration (else three hours) ran out, found by a start or a saved `endsAt` in the past week) call `applyResults`: the pure rules are in `results/player.ts`, `ranking.ts` (the same order as `lib/service/leaderboard.dart`) and `season.ts`. XP: 100 for a finished game, 20 per mission, +50 with no hints, 50 per new badge. Season points: 100, 75, 60, then 50 minus 5 per place, never under 10. Seasons follow the calendar in Romania: `2026-autumn`, "Toamna 2026". The memory marks a player as counted, and `crews/{id}/results/{eventId}` a crew, so a rerun counts nobody twice; `resultsComputedAt` is written last.
