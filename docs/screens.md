# Screen-by-screen behaviour

Companion to `features.md` (route table + architecture). Here: what each screen shows/does, its user-visible Romanian strings, validation and notable behaviour. Paths are under `lib/features/`.

## Entry / auth
- **LandingPage** (`loader_page/landing_page.dart`) — full-screen Lottie; post-frame calls `AuthUtil.checkUserAndRedirect`. Signed out → `splash`; admin → `adminHome`; user → `home`; if the Firestore `users` doc is missing it does nothing (stuck on the loader).
- **SplashScreen** (`splash/splash.dart`) — SVG background, logo, "Bine ai venit!", buttons "Loghează-te" (→ login) and "Inregistrează-te" (→ register).
- **LogInScreen** (`log-in/`) — email + password with validators ("Te rugăm să introduci adresa de email/parola"); "Logare cu Google"; **"Logare cu Facebook" is a placeholder (`onTap: () {}`)**; "Ai uitat parola?" → forgot-password. Success → `pushReplacementNamed(Routes.redirect)` (re-runs role redirect). Errors shown as raw `e.toString()` in a SnackBar (English messages from `AuthenticationRepository`).
- **Register** (`sign-up/screen/register.dart`) — chooser: email (→ `signup`), Google, Facebook (button present, same placeholder pattern), link to login.
- **RegisterScreen** (`sign-up/screen/sign_up.dart`) — email (regex), first name, last name, password (≥ 6 chars), confirm password. `SignUpController.register` → `SignUpService.register` creates auth user + `users` doc (role defaults USER, stores FCM token). SnackBar 'Account created successfully!' → `redirect`. Note: `userRepo.saveUser` is **not awaited**.
- **ForgotPasswordScreen** — email → `FirebaseAuth.sendPasswordResetEmail`; maps `invalid-email` / `user-not-found` to RO messages. `ForgotPasswordService.sendLink` is the thin wrapper over `sendPasswordResetEmail`.

## Visibility rules actually implemented
- `EventType`/`StireType` (PUBLIC/PRIVAT, PUBLICA/PRIVATA) only change badge colour/label (`EventImage`, `StireCard`) and filter results. **There is no access control** — private events/news are listed to everyone.
- Role is checked only at login redirect; screens/routes themselves do not verify `Role.ADMIN`.
